Metamorph

An agentic metamorphic testing framework for computer vision models.

We can measure a vision model's accuracy on its test set — but we have no way to check it against fog, night, motion blur, glare or occlusion, because those inputs have no labels and no test oracle.

Problem and users02 / 10
Who has the problem

Any team shipping a trained detector, segmenter or tracker — autonomous driving, ADAS, agriculture, medical imaging, security — plus the ML researchers and QA engineers who must sign off on it.

Why it matters

The held-out test set never contains the weather, lighting and camera conditions the model meets in deployment. Models fail silently and the failures concentrate on vulnerable classes — pedestrians, cyclists — where an error is most costly. There is no standard method, no oracle, and no coverage measure for this today.

Current workflow

  • Collect & label a dataset
  • Train the model
  • Report accuracy / mAP on a held-out split
  • Robustness? checked ad-hoc — a few hand-picked images, hand-written augmentations, per person, per project
  • Ship

The gap sits between step 3 and step 5.

R&D / recent technical work04 / 10

Sources we build on

  • Metamorphic testing — Chen et al., ACM CSUR 2018: test without an oracle via relations between inputs and outputs.
  • MT for deep models — DeepTest (ICSE 2018), DeepRoad (ASE 2018): GAN weather for driving models — but hand-fixed relations.
  • The 21-MR library for image classification — our general-purpose starting set.
  • InstructPix2Pix — Brooks et al., CVPR 2023: edit an image from a text instruction.
  • CLIP — Radford et al., ICML 2021: image↔text similarity, used here as the semantic gate.
  • Tool-using LLM agents — plan-act-observe loops for MR discovery.

What we took from it

  • MT turns "no labels" into "a checkable relation" — the right primitive for deployment conditions.
  • Generative edits look real, but can silently change the scene → a semantic-preservation check is non-negotiable.
  • A fixed MR set does not transfer across domains → discovery must be driven by a domain description and by evidence collected so far.
  • The LLM must never decide pass/fail — deterministic transforms and objective oracles do.
Complex computing challenge05 / 10
  • No ground truth for the oracle. "Should this transform change the output, and how?" must be synthesised per relation type — invariant, predictable, additive, relational — across classification, detection, segmentation and tracking.
  • Open-ended relation space. The agent proposes new relations from a domain description and accumulated failures; each must pass schema, task-compatibility, domain, feasibility and semantic checks before it can run.
  • Generative transforms break silently. An edit can add or remove objects — needs a CLIP gate with a regenerate-or-fallback loop.
  • Search under budget. transform × image × parameter is a huge space; exhaustive testing is infeasible → adaptive, evidence-guided selection.
  • Reproducible verdicts from a pipeline that contains a stochastic LLM and a stochastic image editor.

CCP mapping

  • Depth of analysis & abstract reasoning
  • No standard, off-the-shelf solution
  • Novel integration: VLM + LLM + editor + CLIP + model + oracle + memory
  • Conflicting requirements: realism ⟷ semantic fidelity ⟷ coverage ⟷ budget

Main modules

Model adapter · Bootstrap sweep · MR Discovery Agent · MR Validator · Adaptive Selection Agent · Transformation Engine (InstructPix2Pix + deterministic) · Semantic Validator (CLIP) · Task-aware Oracle · Failure Analyzer · Orchestrator

Contribution

A domain-adaptive agentic MT framework that (1) discovers and validates new metamorphic relations from a plain-language domain description and accumulated failure evidence, (2) executes them with realistic generative or deterministic transforms behind a CLIP semantic gate, (3) judges them with task-aware oracles across four CV tasks, and (4) selects tests adaptively in a closed evidence-driven loop — producing an interpretable robustness and coverage report.

POC-lite / feasibility evidence07 / 10
data path proven

10 real KITTI street scenes + ground-truth boxes pulled from Hugging Face; deterministic + generative-style transforms (fog · rain · night · dusk · haze · glare · motion blur · occlusion · rotation · insertion) generated offline and rendered with detection overlays.

The full pipeline runs end-to-end: pick → describe → plan relation → transform → CLIP gate (incl. a regenerate case) → model → oracle → memory.

Evaluation plan and risks08 / 10

How success is measured

  • Oracle validity — verdicts vs human judgement on a labelled sample  ≥ 90% agreement
  • MR discovery quality — % of proposed relations that pass the validator and expert review
  • Semantic gate — CLIP precision/recall vs human "did the meaning change?" labels
  • Fault-finding power — real violations surfaced vs a manual audit and vs the fixed-21-MR baseline
  • Coverage — relation-type and condition coverage reached within budget
  • Reproducibility — identical inputs → identical verdicts

Tool / API / GenAI boundary

GenAI is used to propose relations and edit images — every output is validated and can be rejected. The oracle, the metrics and every pass/fail decision are deterministic code. Third-party, all open / research-licensed: HF datasets, an LLM, InstructPix2Pix, CLIP. Our work: the agents, validators, oracles, orchestration and UI.

DEI, ethics and legal10 / 10

DEI

The framework's purpose is equity in ML reliability. It deliberately surfaces failures on under-represented classes and conditions — pedestrians at night, darker skin tones under low light, regional weather — and reports per class and per condition, so disparities are visible instead of hidden in an average. Test scenes and domain descriptions are chosen to span geographies, lighting and appearance.

Ethics

No human-subjects data collection. Public research images with visible faces are handled per dataset terms (blurred on export where required). We never claim "production ready" — the report always states coverage and remaining budget, so results cannot be cherry-picked into a safety claim.

Legal

Datasets under their licences — KITTI: CC BY-NC-SA 3.0, non-commercial research only. Model weights (CLIP, InstructPix2Pix) and the LLM under their own terms. All third-party components isolated behind interfaces; the framework, agents, oracles and UI are the group's own work. Testing memory stores only image ids, transform parameters and verdicts — no PII.
